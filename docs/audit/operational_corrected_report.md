# 300/100 데이터 확장과 코드 정리 기록

## 1. 데이터 확장

초기 실행은 train 90일·test 10일을 사용했습니다. 논문의 300일·100일 설명에 맞추기 위해 가격 범위와 표본을 다음과 같이 늘렸습니다.

| 구분 | 현재 범위 | 행 수 |
|---|---|---:|
| AR 직전 이력 | 2013-03-26 | 12 |
| Train | 2013-03-27–2014-01-20 | 3,600 |
| Test | 2014-01-21–2014-04-30 | 1,200 |
| DA 가격 | 2013-03-26 00:00–2014-04-30 23:00 | 9,624 |
| RT 가격 | 2013-03-26 00:00–2014-04-30 23:00 | 9,624 |

최종 train·test에는 POWER, DA, RT가 모두 있으며 합성 RT 가격이나 forward fill을 사용하지 않았습니다.

## 2. 논문 제안 모형 MILP 계산 방식 변경

90일 train에서는 모든 관측에 binary를 두어도 계산이 가능했습니다. Train을 300일로 늘리면 논문 제안 모형 pooled MLR에 3,600개 binary가 생겨 계산 부담이 크게 증가합니다.

목적함수를 바꾸지 않고, 관측별 surplus와 shortage의 목적계수 합을 이용해 binary를 축소했습니다.

- 계수 합이 양수: surplus·shortage의 동시 증가가 불리하므로 binary 없이도 최적해에서 상보조건 성립
- 계수 합이 0: 둘의 공통 부분을 제거해도 약정량과 목적값이 변하지 않음
- 계수 합이 음수: 인위적인 동시 surplus·shortage를 막기 위해 binary 유지

| 모형 | 축소 전 binary 후보 | 축소 후 binary |
|---|---:|---:|
| 논문 제안 모형 AR 12개 합계 | 3,600 | 1 |
| 논문 제안 모형 MLR | 3,600 | 1 |

## 4. 남아 있는 가정

표본 날짜, source-naive timestamp의 UTC 해석, GEFCom과 MISO 자료의 timestamp 결합, SSRD·TSR accumulation grouping, bounded oracle와 gap 정의는 현재 프로젝트에서 정한 조건입니다.

현재 결과는 shortage penalty 비율 `0.5`($PC_i=0.5DP_i$), `W1=1`, `W2=20` 한 조합만 사용했습니다. 다른 penalty·가중치 조합에 대한 민감도 분석은 아직 수행하지 않았습니다.

데이터 크기는 논문의 300일·100일 설명에 맞춨지만, 논문이 사용한 정확한 표본과 시간대를 확인한 것은 아닙니다.
