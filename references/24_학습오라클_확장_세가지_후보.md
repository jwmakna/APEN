# 24. 학습 오라클 확장(3후보) 상세

## 배경

`23_4개모형_수식대응_일반LAD정책반영.md`의 제안 모형(AR/MLR) 차이점 표에서
"학습용 오라클 → `{0,S,설비최대1.0}` 3후보(`operational_corrected` 방식),
평가는 `{0,S}`만 사용"이라고 한 줄로만 정리했던 내용을 여기서 자세히 푼다.

## 왜 오라클이 두 군데(학습/평가)에서 따로 필요한가

제안 모형(Eq.9/10)의 목적함수는 W1 항(달러 단위 경제손실)과 W2 항(0~1
비율 단위 예측오차)을 더한다. 이 둘의 크기 자릿수가 완전히 다르므로,
**W1 항을 그 시간대에서 "이론상 가능한 최대 이익"으로 나눠 0~1 근처로
정규화**한다. 이 나누는 값(`denom_h`)을 구하는 데 필요한 것이 "학습
오라클"이고, 논문 Eq.(9a)/(10a) 원문에는 이 정규화 자체가 없다(19번
문서). 평가 단계(nRMSE·gap 산출)에서 쓰는 오라클은 이것과 별개로, 논문
Eq.(13)이 정의하는 오라클을 그대로 쓴다.

## 학습 오라클의 3개 후보

시간 t, 실제발전량 S_t, DA가격 DP_t, RT가격 RP_t, 벌금단가 PC_t(=penalty_rate×DP_t)에 대해:

| 후보 | 약정량(x_t) | 이익 계산식 | 의미 |
|---|---|---|---|
| ① 약정 0 | x_t = 0 | `scale × (RP_t × S_t)` | 아무것도 약정 안 하고, 실제 발전량 전부를 실시간가격에 판매 |
| ② 약정 = 실제발전량 | x_t = S_t | `scale × (DP_t × S_t)` | 부족·잉여 없이 정확히 맞춰 일간전가격에 전부 판매 |
| ③ 약정 = 설비최대 | x_t = 1.0 | `scale × (DP_t×1.0 + RP_t×surplus − PC_t×shortage)`, surplus=max(S_t−1,0), shortage=max(1−S_t,0) | 무조건 설비 용량 전체(1.0)를 약정하고, 부족분은 벌금을 물어서라도 채움 |

`oracle_profit_train[i] = max(①, ②, ③)` — 세 후보 중 가장 이익이 큰
값을 그 표본의 학습용 오라클 이익으로 삼고, 시간대 h의 모든 학습표본에
대해 합산한 것이 `denom_h`다.

```python
profit_commit_0      = CAPACITY_MW * DURATION_HOURS * (rt_i * actual_i)
profit_commit_actual = CAPACITY_MW * DURATION_HOURS * (da_i * actual_i)
surplus_if_full  = max(actual_i - 1.0, 0.0)
shortage_if_full = max(1.0 - actual_i, 0.0)
profit_commit_1  = CAPACITY_MW * DURATION_HOURS * (
    da_i * 1.0 + rt_i * surplus_if_full - penalty_i * shortage_if_full
)
oracle_profit_train[i] = max(profit_commit_0, profit_commit_actual, profit_commit_1)
```

## 평가 오라클(Eq.13)과의 차이 — 왜 ③이 평가에는 없는가

논문 Eq.(13)과 §4.2 본문("일간전 가격이 실시간 가격보다 높으면 약정량은
생성된 태양광 에너지만큼 최대한 많아야 하고, 그렇지 않으면 약정을
0으로")은 오라클을 **①②(0 또는 실제발전량) 두 값 중 선택**으로만
서술한다. ③(설비최대) 후보는 논문 어디에도 없다.

③을 학습 정규화에서만 쓰고 평가에서는 뺀 이유: `16_optimality_gap과_
오라클_정리.md`에서 이미 증명했듯, 벌금률이 100%보다 작으면(이 실험은
50%) `0.5×(1+S) ≥ S`가 항상 성립해 **③이 거의 항상 ①②보다 이익이
크다** — 그래서 ③을 평가에도 쓰면 오라클 이익이 비현실적으로 부풀어
gap이 51%까지 치솟는 왜곡이 생긴다(실측 확인됨). 반면 학습 정규화의
`denom_h`는 그냥 "W1 항의 크기를 얼마로 나눌지" 정하는 스케일 상수일
뿐이라, ③을 포함해 더 큰 값을 쓰더라도 계수 자체가 왜곡되진 않는다 —
오히려 ③을 빼고 ①②만 쓰면(더 논문에 가까운 정의) 논문의 비교점
W1=1,W2=20에서 계수가 발산(AR nRMSE 103%)하는 문제가 실측으로
확인되어, 부득이하게 ③을 포함한 채로 유지하고 있다.

## 실증 실험: 후보를 하나만 쓰면 어떻게 되나 (z01/블록9, W1=1,W2=20)

"③(설비최대)을 빼면 발산한다"는 주장을 직접 확인하기 위해, **후보를
②(약정=실제발전량) 하나만 쓰도록** 코드를 수정해 재실행했다.

### 실험 1: 제안 모형 AR — 학습 오라클(denom_h)을 ②만 쓰도록 변경

`논문_제안_모형_AR_오라클단일후보_실험용.py` (원본 199번째 줄
`oracle_profit_train[i] = max(...)`를 `oracle_profit_train[i] =
profit_commit_actual`로 교체):

| | nRMSE | optimality gap |
|---|---:|---:|
| 원래(3후보 max) | 38.58% | +3.63% |
| **②만 사용** | **103.52%** | **−8.19%** |

시간대10에서 이진변수 21개, **시간대11(오후 8시, 일몰 직전)에서는
286개**(학습표본 300개 중 거의 전부)가 필요해졌다 — 회귀가 사실상
붕괴해 대부분의 표본이 극단 상태로 몰렸다는 신호. `denom_h`가
작아지면서 W1 계수(`−W1·scale·DA/denom_h`)가 상대적으로 커져, 정확도
(W2 항)보다 "일단 많이 약정" 유인이 압도한 결과다. 흥미롭게도 이 값은
과거(15/19번 문서)에 기록해둔 "{0,S} 2후보로 학습했을 때 AR nRMSE
103%까지 치솟았다"는 결과와 사실상 같다 — 이 블록은 대부분 시간대에서
DA>RT라 `max(0,S)`가 사실상 `S` 하나로 수렴하기 때문이다.

### 실험 2: 기본 모형 AR — 평가 오라클을 ②만 쓰도록 변경

`기본_모형_AR_오라클단일후보_실험용.py` (원본 284번째 줄
`oracle_profit_i = max(profit_if_commit_zero, profit_if_commit_actual)`를
`oracle_profit_i = profit_if_commit_actual`로 교체):

| | nRMSE | optimality gap |
|---|---:|---:|
| 원래({0,S} 2후보) | 38.78% (무변화) | +3.696% |
| **②만 사용** | **38.78% (무변화)** | **−6.115%** (악화) |

### 두 실험의 결정적 차이 — "오라클이 학습에 쓰이는가"

| | 기본 모형 AR | 제안 모형 AR |
|---|---|---|
| 오라클이 쓰이는 곳 | 평가(gap 계산)뿐 | **학습(denom_h) + 평가** |
| 후보를 줄였을 때 nRMSE | **무변화** (38.78%→38.78%) | **붕괴** (38.58%→103.52%) |
| 후보를 줄였을 때 gap | 악화(+3.7%→−6.1%) — 오라클이 인위적으로 약해져 실현이익이 상대적으로 좋아 보이는 착시 | 악화(+3.6%→−8.2%) — 계수 자체가 뒤틀린 결과 |

**결론**: 기본 모형은 오라클 정의에 안전하다(예측 자체는 절대 안
바뀌고, 사후 채점 지표인 gap만 흔들린다). 제안 모형은 오라클 정의가
학습 과정 자체에 개입하므로 훨씬 취약하며, 이번 실험은 ③(설비최대)
후보가 학습 안정성에 실질적으로 필요하다는 것을 다시 한번 실증했다.
